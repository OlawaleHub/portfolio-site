(01) — About my work

What I do

I specialise in web and cross-platform mobile development. My work spans cross-platform mobile engineering in Dart and Flutter, web development, and data analysis, built on hands-on experience in laboratory research, administrative support, customer management and teaching.

My route here was not a straight line. I studied biological sciences first, and that training still shapes how I work: form the hypothesis, run the experiment, look honestly at what the result says. In practice that means caring about the things that are easy to skip — how fast the page paints, what happens when the connection drops, whether somebody can actually finish the task they came for.

I currently work as a software engineer on the web and mobile team at Refcrypt Labs in Lekki, Lagos. I also founded and run Light a Path, a youth empowerment initiative. When I am not building, I mentor junior developers.

Web development

Production-grade websites and web apps with Next.js and React — responsive, accessible and built to be found. I care about Core Web Vitals, semantic markup, real keyboard navigation and the unglamorous work of making a page load quickly on a mid-range Android phone.

Mobile app development

Cross-platform mobile apps with Dart and Flutter — one codebase, Android and iOS, clean architecture and state management that does not fight you six months later. Includes API integration, local persistence and release builds.

Apps that assume the network will fail, because in Lagos it often does. Service workers, IndexedDB queues and background sync so that a user can complete the task first and reconcile with the server later.

(06) — Working notes

How I approach the work

How I
work

01 — Assume the network will fail

Any product I build for a Nigerian audience is designed offline-first. The Lagos emergency app queues reports in IndexedDB and replays them through background sync, because the moment someone needs it most is the moment the connection is worst.

02 — Let the non-technical person own the content

If an editor has to ask a developer to publish an article, the platform has failed. I embed a no-code CMS studio and use incremental revalidation so publishing stays independent and the site stays fast.

03 — Write tests where money moves

The governance contracts handle payments, refunds and quorum, so they carry the heaviest test coverage in anything I have built. Bugs in a voting contract are not cosmetic.

04 — Say what is actually finished

Several of my projects ship with honestly documented limitations — placeholder phone numbers, a dispatch endpoint that still needs wiring. I would rather mark the gap than imply it is closed.
